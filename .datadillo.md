# Datadillo review guidance — skaledata/cli

The `skale` CLI (Go, released via goreleaser). Talks to the SkaleData
control-plane API for auth, cloud management, Airflow local dev, and
deploy flows. Distributed to customer engineers, so backward compatibility
of the command surface matters more than in an internal tool.

## Highest-signal review dimensions (in order)

1. **Backward compatibility of the command surface.** `skale auth`,
   `skale clouds`, `skale airflow` and their subcommands are the public
   contract. Renaming a flag, removing a subcommand, or changing the
   shape of stdout for a scripted command is a breaking change — flag
   hard and require a major-version bump note.
2. **Auth handling.** No long-lived tokens on disk in plaintext. API
   keys / OAuth tokens should be stored via the OS keyring where
   possible, falling back to `~/.skale/` with `0600` perms. Never log
   the token; never send it to a URL other than the configured
   control-plane host. Watch for accidental token echoes in error paths.
3. **Cross-platform correctness.** goreleaser targets macOS (amd64 +
   arm64) and Linux (amd64 + arm64) at minimum. Watch for:
   - Path separators (`filepath.Join`, not string concat with `/`)
   - Case-sensitive filenames (macOS default is case-insensitive; CI is
     usually case-sensitive)
   - `os/exec` calls to tools that may not exist on the user's box
     (`kubectl`, `helm`, `docker`) — check `LookPath` and give a helpful
     error, don't panic.
4. **Deploy flow correctness.** `skale airflow deploy` now runs via the
   Helm-native path (Phase 27) and supports DAG-only deploys (Phase 29).
   Any change to deploy semantics needs to keep both flows working.

## Repo-specific gotchas (flag these hard)

- **Config file schema changes.** `~/.skale/config.yaml` is written by
  older CLI versions. Adding a new required field breaks upgrades.
  Additive-only unless there's a migration.
- **`context.Context` propagation.** Every HTTP call to the control
  plane must take a `ctx` — a Ctrl-C from the user should cancel the
  in-flight request cleanly.
- **Error output.** User-facing errors should be actionable ("run
  `skale auth login` first"), not stack traces. Reserve verbose
  output for `--debug`.
- **Version reporting.** `skale --version` must reflect the goreleaser
  tag (typically via `-ldflags "-X main.version=..."`). Flag diffs that
  break the version string.

## What to skip

- `go.sum` diffs unless a new module was added.
- `gofmt` / `golangci-lint` chores — those gate at CI.
- Comment / godoc-only changes.

## Tone

Terse. Where a change could break existing customer scripts (CI, cron,
Makefiles that invoke `skale`), call it out as a breaking change and
suggest a deprecation path.
